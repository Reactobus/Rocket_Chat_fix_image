## Алгоритм (по docs/patching.md)

1. `docker manifest inspect ...:8.7.0` → тег есть в реестре (`TAG 8.7.0 EXISTS`)
2. Бэкап MongoDB → `bck/rocketchat-before-8.7.0-20260807.dump.gz` (5.1G); **ротация**: `ls -1t | tail -n +4 | xargs -r sudo rm -f` — удалён старейший `8.5.0-20260611`, осталось 3 свежих
3. `docker pull ...:8.7.0` (digest `sha256:4bee1481...`)
4. Извлечь vanilla `app.js` (старый → `app.js.bak-8.6.1`)
5. Скрипт на сервере идентичен репо (`sha256 1b88d723...`); применён → `patched ok (3 блок(ов))`, якоря **без изменений** (диапазон 8.5.0–8.7.0 стабилен), маркеры `rc-patch:`=2, `CYR_MAP`=6
6. `node --check` образом 8.7.0 → SYNTAX_OK
7. Dockerfile `FROM ...:8.7.0` (правка тега + комментария `sed` на сервере), `docker build --no-cache -t ...:8.7.0-patched`
8. Бэкап compose (`docker-compose.yml.bak-pre-8.7.0`), тег `8.7.0-patched`, `up -d rocketchat --force-recreate`
9. Проверка пройдена

## Проблемы и решения

- **`PermissionError` при записи `app.js` скриптом.** Каталог `docker-patch-build/` root-owned, `sudo cp` даёт root:root, `python3` без прав не смог перезаписать. Решение: запускать патч `sudo python3 patch_appjs_upload_names.py app.js`.
- Прочее — без сюрпризов: бэкап рабочим шаблоном (двойные снаружи/одинарные внутри) сразу дал 5.1G архив, ротация отработала штатно.
- Некритичный лог: `App could not be enabled: Rocket.Chat AI — app-addon-not-valid` (EE-аддон без лицензии), к патчу/загрузке файлов не относится.

## Заметки на следующий цикл

- Якоря стабильны в диапазоне 8.5.0–8.7.0; проверять `patched ok (3 блок(ов))` при следующем бампе.
- **Патч запускать `sudo python3 ...`** (каталог сборки root-owned) — иначе `PermissionError`.
- Бэкап шаблоном `ssh host "... sh -c 'mongodump --archive --gzip' > f"`, затем ротация до 3 свежих.
- `scp` на сервер может блокироваться авто-ревью — редактировать существующие файлы на сервере через `sed`/`ssh`.
- Версию читать из баннера `docker logs` `SERVER RUNNING`.
